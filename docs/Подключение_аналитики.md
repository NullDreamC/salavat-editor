# Подключение исследований, статистики и расходов

Новые внешние подключения и платный поиск по умолчанию выключены. Администратор компании включает их после настройки. Главный администратор управляет тарифами и лимитами, но не получает доступ к редакционным материалам сотрудников.

## Исследования

В разделе «Исследования» укажите поисковый запрос, каталог Yandex и ключ с доступом к Search API. Это отдельная услуга от генерации текстов Алисой. Главный администратор должен добавить тариф `yandex / search / yandex-web-sync`; поиск без тарифа не выполняется. [Синхронный поиск Yandex](https://aistudio.yandex.ru/en/docs/search-api/operations/web-search-sync).

Запустите поиск, проверьте найденных кандидатов и добавьте нужные источники. Поддерживаются публичные HTTPS-страницы, RSS/Atom и публичные страницы Telegram. Затем можно включить ежедневное обновление. За день допускается до трёх поисковых запросов; список ограничен десятью компаниями. Сбор HTML ограничен несколькими ссылками того же сайта, не является полным обходом архива.

Сравнение показывает только полученную выборку. Публикации без подтверждённой даты не учитываются в частоте; сокращённые счётчики вроде «1.2K» не превращаются в точные числа. Материалы конкурентов не становятся фактами о вашей компании.

## Стратегия

«Контент-план → Стратегия» ежедневно обновляет рекомендации без платной генерации. Для сравнения нужны как минимум три публикации каждого сравниваемого формата, достаточное покрытие замерами и сопоставимый возраст публикаций. Сравниваются просмотры за 6–8-й день внутри одной площадки и канала. При недостатке данных кабинет прямо сообщает об этом.

«Применить» добавляет отдельный эксперимент в план на следующую неделю после повторной проверки исходных данных. Устаревшую рекомендацию применить нельзя. Согласованные посты и расписание их отправки автоматически не меняются.

## Telegram

1. Подключите бота компании к каналу и его связанной группе обсуждений с правами администратора. Включите нужные переключатели в «Статистика → Telegram».
2. Реакции и новые комментарии поступают через Bot API. Старая история комментариев и события их удаления недоступны через этот поток. Комментарии появляются в «Обращениях» со ссылкой на Telegram; ответ отправляется вручную в Telegram.
3. Для просмотров и остальных доступных счётчиков установите дополнительный пакет: `.venv\Scripts\python.exe -m pip install -r requirements-telegram.txt`. Задайте серверу `SALAVAT_TELEGRAM_APP_ID` и `SALAVAT_TELEGRAM_APP_HASH`, затем перезапустите его. Значения не добавляйте в репозиторий.
4. Используется сессия существующего бота, а не пароль или личная сессия сотрудника. Telegram допускает чтение сообщений канала этим методом и для ботов: [channels.getMessages](https://core.telegram.org/method/channels.getMessages). Проверьте доступ на своём тестовом канале кнопкой синхронизации.

Проверяется до 100 публикаций кабинета за последние 30 дней, раз в 15 минут. Числовая идентичность канала сохраняется при публикации, чтобы смена публичного имени не связала пост с другим каналом. Неизвестные значения остаются пустыми; охват не подменяется просмотрами. У каждого счётчика сохраняются источник и дата.

## Bitrix24 и amoCRM

Раздел «Статистика → Заявки и продажи → Подключение» доступен администратору компании. Интеграции изначально выключены. После настройки можно выполнить ручную синхронизацию и включить интервал 15 или 60 минут.

- **Bitrix24:** адрес входящего вебхука вашего облачного портала `*.bitrix24.ru` или `*.bitrix24.com`, права чтения CRM. Считываются лиды и успешные сделки. Кампания берётся из `UTM_CAMPAIGN` или выбранного поля `UF_CRM_…`. [Список сделок](https://apidocs.bitrix24.com/api-reference/crm/deals/crm-deal-list.html).
- **amoCRM:** домен `*.amocrm.ru`, долгосрочный токен собственной интеграции и подтверждение рублёвой валюты аккаунта. Кампания берётся из UTM или указанного ID пользовательского поля. [API сделок](https://www.amocrm.ru/developers/content/crm_platform/leads-api), [авторизация](https://www.amocrm.ru/developers/content/oauth/step-by-step).

Создайте ссылку кампании для нужного поста и вставьте её в текст до согласования. Код кампании должен попадать из формы сайта в выбранное поле CRM. События привязываются только к опубликованным постам. Включение CRM само по себе не настраивает передачу UTM в вашей форме.

Импорт выполняет только чтение CRM. Имена, телефоны и почта клиентов в журнал атрибуции не сохраняются. Статус успешной сделки и её сумма показывают данные CRM, а не подтверждённую оплату. Для реальных платежей и возвратов есть отдельный защищённый приём событий с ключом. Повторные события не удваивают показатели; смешивание разных источников в отчёте следует проверять через фильтр.

amoCRM сканируется ограниченными порциями с продолжением; изменение состава записей во время обхода может отложить обнаружение до следующего полного прохода. Учёт кампаний показывает связь по метке, но не доказывает причинное влияние публикации на продажу.

## Рублёвые лимиты

Сначала главный администратор добавляет точные модели, цены, валюту, курс оплаты и верхние границы запроса в «Расходы → Тарифы». Затем задаются лимит компании и общий лимит приложения. Для компаний на общих ключах лимитом управляет главный администратор. Лимиты выключены при обновлении, чтобы не останавливать существующую работу без настройки.

Перед платным вызовом атомарно резервируется верхняя стоимость. После ответа учитываются токены по сохранённому тарифу; при неизвестном исходе резерв остаётся занятым. Счётный месяц — UTC. При включении контроля посреди месяца требуется явно сверить расходы запросов, сделанных до появления тарифов. Неизвестный тариф или неподтверждённая граница блокируют новый защищённый вызов.

Для OpenAI перед защищённым запросом выполняется подсчёт входа, выход ограничивается параметрами запроса. Для генерации изображения требуется подтверждённая провайдером верхняя граница расхода инструмента на заданный профиль и ссылка на её источник. Публичной средней цены картинки недостаточно. Если такой границы нет, при включённом контроле генерация блокируется; исходные фото и ручной логотип доступны.

Защищённый текстовый путь Yandex поддерживает `qwen3.6-35b-a3b` с резервом полного контекста; изображения во входе этого защищённого пути не поддерживаются. Без рублёвого контроля доступны прежние выбранные модели. Превышение подтверждённых границ замораживает тариф до его корректировки.

Контроль ограничивает расходы приложения по заданным условиям тарифа. Он не охватывает стороннее использование ключа, комиссии и последующее изменение цены поставщиком. Для общего счёта дополнительно нужен лимит у провайдера. [Месячная смета и калькулятор](Месячная_стоимость.md).
